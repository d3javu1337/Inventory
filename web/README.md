# Asset Inventory Web

Русскоязычная административная SPA-панель проекта Asset Inventory.

## Стек

- React 18, TypeScript, Vite;
- Material UI;
- React Router;
- TanStack Query;
- Vitest, Testing Library и Playwright;
- OpenAPI Typescript для генерации контрактов.

## Локальный запуск

```powershell
npm install
npm run dev
```

Vite проксирует `/api` на `http://localhost:5147`. Альтернативный адрес API задается через `VITE_API_BASE_URL`.

## Команды

```powershell
npm run build
npm test
npm run test:e2e
npm run generate:api
```

Генерация API ожидает запущенный backend в Development, публикующий `/openapi/v1.json`.

Формы проверяют данные до отправки и показывают ошибки на русском возле полей. Даты проверяются по календарю; время вводится в часовом поясе Asia/Yekaterinburg и отправляется в UTC. Пустая стоимость отличается от нулевой; год и период расписания должны быть целыми числами.

Кнопка замка «Сменить пароль» рядом с выходом открывает форму текущего и нового пароля с повтором. После сохранения текущий браузер получает новую сессию, а прежние access/refresh на остальных устройствах отзываются. Ошибка текущего пароля не стирает форму; истёкший access token обновляется только после challenge-401 с однократным повтором команды.

Список инвентаризаций ищет по номеру, UUID, описанию, МОЛ и исполнителю по всем серверным страницам. Поиск сочетается с фильтрами статуса, типа и основания; URL сохраняет их и номер страницы при возврате из карточки. МОЛ/область и исполнитель видны прямо в таблице.

В аудите доступны поиск объекта/пользователя/ID запроса, действие, тип/ID сущности, пользователь и период полных дней Екатеринбурга. Все фильтры сохраняются в URL; число действий и страницы считаются сервером после фильтрации. «Система» включает фоновые действия без пользователя. Из карточек ОС и инвентаризации кнопка «История действий» сразу открывает нужный объект; неверный период блокируется до запроса.

Проверка от 2026-10-03: production-сборка, 10 unit-тестов и 14 Playwright-сценариев проходят. Для `npm run test:e2e` сначала выполните `npm run build`. Тесты валидации подменяют API и проверяют блокировку некорректных запросов и отправку исправленных данных без изменения рабочей БД. Это проверка фронтенда, а не полная интеграционная приёмка backend. По умолчанию используется установленный Chrome; другой путь задаётся через `PLAYWRIGHT_CHROME_PATH`.

## Docker Compose

Из корня проекта:

```powershell
docker compose -f deploy/docker-compose.yml up -d --build
```

Web-панель будет доступна на `http://localhost:5173`, API — на `http://localhost:5147`.
