# Mobile

Android-приложение для сотрудников отдела инвентаризации.

Основные функции:

- просмотр назначенных инвентаризаций;
- сканирование QR-кодов;
- фиксация состояния основных средств;
- завершение обхода назначенным исполнителем;
- подтверждение результатов этим же исполнителем.

Целевой стек: bare React Native.

## Реализованный MVP

Приложение реализует онлайн-сценарий инвентаризатора:

1. Вход через `/api/v1/auth/mobile/login`.
2. Восстановление сессии через refresh token в Android Keystore.
3. Просмотр назначенных проверок через `/api/v1/mobile/inventories`.
   В списке есть поиск по номеру, UUID, МОЛ, исполнителю и описанию; он применяется на сервере по всем страницам и сохраняется при смене категории. Черновики, требующие внимания/доработки и отменённые проверки доступны отдельными категориями. Карточки показывают исполнителя и МОЛ; чужие назначения не выдаются поиском.
4. Рабочий список ещё не найденных устройств, поиск и серверные страницы по 20 строк. Найденные устройства после сохранения исчезают из него, но остаются в отдельном списке результатов; посторонние QR не смешиваются с ОС.
5. Сканирование QR камерой Android или из видеопотока браузера. В debug-сборке UUID можно ввести вручную.
6. Фиксация состояния `Serviceable`, `Damaged`, `Unusable`.
7. Завершение неполного обхода исполнителем с явным предупреждением о ненайденных ОС.
8. Подтверждение или отклонение результатов.
9. Смена своего пароля кнопкой «Пароль» в списке проверок: проверка текущего, нового и повтора. Текущее устройство получает новую сессию, остальные сеансы отзываются. При ошибке введённые значения остаются в форме до повтора или ухода с экрана.
10. Сохранение ИНВ-1 PDF/XLSX из завершённой назначенной проверки. Android предлагает системный выбор места сохранения; mobile web скачивает файл. Отмена не показывает успех; ошибки можно повторить. Файл загружается с авторизацией и однократным refresh/retry после challenge-401, без токенов в ссылке.

Нативное сохранение использует `ReportFilesModule` (Android Storage Access Framework), зарегистрированный в `MainApplication`; после обновления с APK без этого модуля требуется установить новую сборку. Дополнительные разрешения на файловую систему не нужны. Debug APK собран для всех четырёх настроенных архитектур и требует запущенного Metro; проверка системного диалога на физическом устройстве остаётся отдельной приёмкой.

## Запуск

Требования: Node.js 20.19.4+, JDK 17, Android SDK Platform 35, Build Tools 35, NDK 27.1.12297006, CMake 3.22.1 и ADB. React Native CLI устанавливается через зависимости проекта.

```powershell
npm install
npm start
npm run android
```

### Демонстрация через OBS на одном ПК

```powershell
npm run web
```

1. Запустите обновлённый локальный API и откройте в админке карточку ОС, которое входит в активную проверку. Скачайте актуальную PNG-этикетку.
2. В OBS добавьте PNG как источник «Изображение». Увеличьте его в кадре, сохранив белые поля вокруг квадрата. Нажмите «Запустить виртуальную камеру». [Руководство OBS](https://obsproject.com/kb/virtual-camera-guide)
3. Откройте [мобильный интерфейс](http://127.0.0.1:5174) в Chrome или Edge, войдите как назначенный инвентаризатор и откройте «Сканировать QR». Разрешите доступ к камере. В списке «Источник камеры» выберите **OBS Virtual Camera**. При автоматическом выборе приложение отдаёт ей предпочтение, когда браузер показывает имена устройств.
4. Когда откроется карточка ОС, укажите состояние и нажмите «Сохранить результат». Для следующего скана подайте следующий QR в OBS.

OBS, браузер и API работают на одном ПК. Vite проксирует `/api` на `http://127.0.0.1:5147`. Для изолированного стенда перед запуском Vite задайте `$env:ASSET_WEB_API_TARGET = 'http://127.0.0.1:15147'`. Refresh token браузера хранится в localStorage.

Если OBS Virtual Camera отсутствует в списке, запустите её в OBS, затем заново откройте экран сканирования или нажмите «Повторить». [Диагностика виртуальной камеры OBS](https://obsproject.com/kb/virtual-camera-troubleshooting)

Для Android-эмулятора debug-сборка использует `http://10.0.2.2:5147/api/v1`, соответствующий публикации API `5147:8080` в `deploy/docker-compose.yml`. Release-адрес задается константой `RELEASE_API_BASE_URL` в `src/api/client.ts` перед production-сборкой.

Когда Android Emulator показывает виртуальную камеру OBS в списке устройств, её можно передать прямо в заднюю камеру AVD. Подставьте её индекс из первой команды. [Параметры Android Emulator](https://developer.android.com/studio/run/emulator-commandline#common)

```powershell
$emulator = Join-Path $env:LOCALAPPDATA 'Android/Sdk/emulator/emulator.exe'
& $emulator -avd AssetInventory_API34 -webcam-list
& $emulator -avd AssetInventory_API34 -camera-back webcam1 -no-snapshot-load
```

На установленном Windows-эмуляторе 34.2.15 в списке видна только USB-камера. Для демонстрации с OBS на этой конфигурации используйте браузер.

### Сканирование PNG в Android-эмуляторе

В админке откройте «Основные средства», выберите ОС и нажмите «Скачать QR». Эту же этикетку можно распечатать кнопкой «Печать» сразу после сохранения ОС. Для учебного обхода используйте этикетку одного из ОС в составе выбранной проверки.

В PowerShell из корня проекта запустите AVD с PNG на стене и на столе:

```powershell
$emulator = Join-Path $env:LOCALAPPDATA 'Android/Sdk/emulator/emulator.exe'
$label = (Resolve-Path 'C:/путь/к/этикетке.png').Path
& $emulator -avd AssetInventory_API34 -camera-back virtualscene -virtualscene-poster "wall=$label" -virtualscene-poster "table=$label" -no-snapshot-load
```

Запустите Metro и Android debug-приложение из каталога `mobile`. Для тестового API на порту 15147 задайте `$env:ASSET_DEBUG_API_URL = 'http://10.0.2.2:15147/api/v1'` перед запуском Metro. Если Metro уже работал с другим адресом, перезапустите его с `npm start -- --reset-cache`.

В активной проверке нажмите «Сканировать QR». Постер находится в столовой за дверью позади стартовой позиции камеры. Удерживайте **Shift** и двигайте мышью, чтобы повернуться. Для перемещения удерживайте **Shift** и используйте **W/A/S/D**. [Управление виртуальной камерой](https://developers.google.com/ar/develop/c/emulator#move_the_virtual_camera)

Заменить PNG можно в **⋯ → Camera → Virtual scene images** без перезапуска приложения. [Руководство Android Emulator](https://developer.android.com/studio/run/emulator-use-camera)

Проверки:

```powershell
npm run typecheck
npm run lint
npm test -- --runInBand
```

Сборка APK:

```powershell
$env:JAVA_HOME = "C:\path\to\jdk-17"
cd android
.\gradlew.bat assembleDebug
.\gradlew.bat assembleRelease
```

Готовые файлы создаются в:

- `android/app/build/outputs/apk/debug/app-debug.apk`;
- `android/app/build/outputs/apk/release/app-release.apk`.

Текущий `app-release.apk` предназначен для внутреннего тестирования: он подписывается debug-ключом. Перед распространением необходимо настроить отдельный production keystore и заменить `RELEASE_API_BASE_URL` на адрес развернутого backend.

Ручной ввод UUID доступен в debug-сборке.

Проект собирается с `compileSdk 35`, `targetSdk 34`, минимальной Android API 24 и отключенной New Architecture. NDK и CMake используются нативной частью `react-native-screens`.

Ручной ввод исключается из Android release-сборки условием `__DEV__`.
