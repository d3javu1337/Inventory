## Найденные проблемы

### P1: клиентский кеш не изолирован между аккаунтами

Воспроизведено в обоих направлениях:

1. Войти worker1, открыть список/INV-MVP-001, выйти.
2. Войти worker2: видны INV-MVP-001/004 вместо его INV-MVP-002.
3. Обновить список: появляется INV-MVP-002; открыть её и выйти.
4. Войти worker1: остаётся INV-MVP-002, карточка показывает данные второго
   исполнителя из кеша, несмотря на серверный запрет 404.

Причина по коду: общий QueryClient, query keys без userId,
`refetchOnMount:false`; logout очищает session, но не QueryClient.
Это утечка уже загруженных данных на одном клиенте, не обход серверной защиты.
Общий mobile-код означает потенциальную применимость к Android, но нативно
проблема сейчас не воспроизводилась.
Источники: mobile/src/query/QueryProvider.tsx, auth/session.ts,
screens/InventoryListScreen.tsx, screens/InventoryDetailsScreen.tsx.
Снимки: tmp/manual-acceptance-20261004/mobile-worker2-stale-list.jpg,
mobile-cross-account-card.jpg.

### P1: mobile web теряет сессию после reload

Правильный вход worker1 → reload → экран входа. В серверных логах два параллельных
mobile/refresh: первый 200, второй 401. RootNavigator bootstrap effect запускается
повторно в React.StrictMode и не использует общий single-flight. Первый запрос
ротирует токен, второй воспринимается как replay. Нативное поведение не проверялось.

### P2: неверный пароль не даёт видимой ошибки в mobile web

Неверный пароль → Войти → форма без сообщения. Авторизация сервером отклоняется.
LoginScreen использует React Native Alert.alert, который не отображается в web.
Другие Alert-сценарии могут быть затронуты, но ещё не пройдены.

### P2: ошибки в созданном мной SQL init

Расписания содержат Manual/Automatic вместо допустимых CreateDraft/AutoStart.
Чтение через EF потенциально завершится ошибкой enum; административный GET
не выполнен, HTTP 500 не объявляется подтверждённым. Расписания выключены.
Также md5::uuid даёт произвольные UUID, не UUIDv7 по ТЗ. Текущий Zod `uuid()`
принимает проверенный пример, блокировка web-форм этим не подтверждена.
Эти дефекты относятся к моему набору, не к штатному API создания записей.

### P3: Draft не переведён в мобильной карточке

В списке «Черновик», в карточке «Статус: Draft».
В InventoryDetailsScreen отсутствует перевод Draft.
